# Tech

## Стек
- **Фронтенд**: Phaser 4 + Vite + TypeScript, скаффолд `phaserjs/template-vite-ts`. Деплой — статика на GitHub Pages (`game-deploy` skill, `gh-pages -d dist`).
- **Бэкенд**: Google Apps Script Web App, привязанный к приватной Google-таблице. Бесплатно, без отдельного хостинга/сервисного ключа.
- **Ассеты**: пиксель-арт стиль. Источник — `assets-source/raw-pixel/character-sheet-source.jfif` (лист персонажей, добавлен пользователем) → нарезка по координатной сетке (Python/PIL) → удаление белого фона через выделение связных компонент (`scipy.ndimage.label`, порог по белому — не ML, чтобы не размывать чёткие пиксельные края) → `game/public/assets/sprites/*.png`. `pen.png` — процедурный пиксель-арт (рисуется на сетке 48×34 "пикселя" и апскейлится через `NEAREST`, без внешних инструментов). Рендер игры — `pixelArt: true, roundPixels: true` в конфиге Phaser (`src/game/main.ts`); каждый спрайт масштабируется через `setScale(targetHeight / this.height)` в конструкторе, все твины анимаций используют этот `baseScale` как множитель (никогда не абсолютные значения вроде `scaleX: 1.2` — иначе персонаж дёрнется до нативного размера).
- **Устаревшее**: фотореалистичная версия арта (из `ROP.jpg`) заменена пиксель-артом по запросу пользователя. Старые кропы удалены из `assets-source/`.
- **Второй набор ассетов** (`assets-source/raw-pixel/`, добавлен позже): новые более динамичные позы 6 героинь, новая Валькирия + 4 её эмоции (`hero_boss_flying_victory/celebrate/happy/sad`), 4 состояния свина (`pig_dizzy/ko/calm/curled`, `pig` = calm по умолчанию). Эти файлы были экспортированы с шахматным узором вместо реальной прозрачности (JPEG не поддерживает alpha) — удаление фона через заливку от границ + от каждого "острова" фона (`ndimage.label`), а не глобальный порог, чтобы не задеть светлые детали костюмов и не оставить дыры в местах вроде подмышки.
- **Третий набор ассетов** (`assets-source/raw-pixel/СР1..СР9/`) — по 3-4 альтернативные позы удара на героиню (реальный PNG-скриншот из редактора персонажей с уже настоящей альфой, без шахматки — обработка свелась к обрезке по bbox прозрачности, без заливки фона). Экспортированы в `public/assets/sprites/` как `${sprite}_hitN.png` (N=1..3 или 1..4 в зависимости от героя). `Preloader` пытается загрузить `hit1..HERO.MAX_HIT_POSES` для каждого героя и молча пропускает 404 для несуществующих номеров (без плейсхолдера — см. регэксп `_hit\d+$` в `onLoadError`); `HeroSprite` в конструкторе фильтрует по `scene.textures.exists()` и получает список реально доступных поз. `playHit()` при каждом ударе переключает текстуру (`sprite`+`glow`) на следующую позу по кругу (round-robin, `nextHitPoseIndex`) в момент "strike"-стадии твин-цепочки, возвращает дефолтную текстуру в `onComplete`. У Валькирии (`hero_boss_flying`) поз ударов нет — `hitPoses` пуст, ветка чередования просто не срабатывает.
- **`Загон.jfif`** (второй набор) — НЕ пиксель-арт, тот же фотореалистичный 3D-рендер, что был раньше. Не подключён (стилистически не подходит); используется процедурный пиксельный `pen.png`.
- **Свечение по краям** — Phaser 4 убрал `postFX` для отдельных объектов (теперь `camera.filters` — только на уровне камеры целиком). Вместо этого у `HeroSprite`/`Pig` есть "ghost"-копия текстуры позади основного спрайта: увеличена (~1.12x), тонирована в цвет героя, `BlendMode.ADD`, alpha ~0.5 — простой и надёжный способ дать каждому персонажу свой цвет свечения без привязки к нестабильному API.
- **Дорога/дистанция**: `RoadLayer` — второй, гораздо более длинный слой мира (см. `Constants.ROAD`), который рендерит только отдельная камера-миникарта (`RoadCamera`, верхний правый угол). Основная камера его полностью игнорирует (`camera.ignore(...)`), поэтому таблица героев не меняется. При каждом обновлении прогресса миникарта разворачивается на весь экран, "пролетает" вдоль дороги от старой к новой позиции свина и сворачивается обратно в угол — так расстояние ощущается как реальный путь, а не как несколько пикселей движения. `PenScene.onProgressChanged` запускает пролёт только если `ratio` реально изменился (сравнение с `lastRatio`, эпсилон `1e-6`) — иначе `DataPollingService` эмитит `PROGRESS_CHANGED` на каждый опрос (раз в 15с) безусловно, даже без изменений в таблице, и миникарта разворачивалась бы впустую. Открытие пролёта также отложено на `roadDelayMs` (считается в `DataPollingService.diffAndEmit` как время окончания последнего анимированного удара — `(hitCount-1) * HERO.HIT_STAGGER_MS + HERO.HIT_DURATION_MS` — плюс пауза `ROAD.OPEN_DELAY_MS`), чтобы анимация удара героини успевала отыграть на табло, прежде чем экран займёт пролёт по дороге; движение свина/текст пузыря (`pig.setProgress`) при этом остаются мгновенными.

## Надёжность и полишинг (M1-M10, реализованы за один заход после ревью прототипа)

- **Само-восстанавливающееся празднование**: вместо отслеживания `weekStart` — `Pig.celebrated`/`GameState.reachedPen`/`GameState.lastMilestoneRatio` сбрасываются сами, как только `ratio` снова падает ниже соответствующего порога (1 для финала, 0.25 для вех). Просто и надёжно: следующая неделя (или поднятие плана) естественно опускает ratio, что само переоткрывает "защёлку" без специальной логики про календарь.
- **`PIG_REACHED_PEN` несёт `delayMs`** — переиспользует уже посчитанный в `DataPollingService.diffAndEmit` `roadDelayMs`, чтобы финальное конфетти/фанфара не наложились на ещё не доигравшие анимации ударов из того же тика опроса.
- **Камера-игнор для новых FX-объектов**: `RoadCamera.setup()` один раз строит статичные списки `ignore()` для обеих камер при создании сцены. Любой FX-объект, созданный ПОСЛЕ этого (кольцо удара, комикс-текст, afterimage-трейл, летящая цифра), явно регистрируется через новый `RoadCamera.ignore()` passthrough (в `HeroSprite` — через инжектируемый в конструктор callback `onImpactFx`) — иначе он отрендерится и на ~7%-зум мини-карте в углу как визуальный шум. Полноэкранные эффекты (конфетти, виньетка, цветовая вспышка) принципиально не создаются в `PenScene` — их место в `HUDScene`, у которой одна камера и этой проблемы нет вообще.
- **Гейтинг "громких" эффектов**: комикс-текст на ударе показывается только при `delta >= FX.COMIC_TEXT_MIN_DELTA` (Constants.ts) — иначе экран "трещал" бы текстом на каждой мелкой продаже при частых мелких сделках подряд.
- **Параллакс дороги** — `RoadLayer.bg`/`sky` получили `setScrollFactor(0.25)`/`setScrollFactor(0.5)` (дорога/фонари/маркеры остались `1`). Безопасно именно потому что весь `RoadLayer` рендерится ТОЛЬКО камерой-миникартой — расширенная область прорисовки (`bgMargin`/`skyMargin` = `ROAD.LENGTH * (1 - scrollFactor)`) компенсирует то, что камера "укатывается" дальше исходно нарисованной зоны при пониженном scrollFactor.
- **Звук — сырой `AudioContext`, не `Phaser.Sound`**: нет файлов для загрузки, только процедурный синтез (осциллятор + шумовой буфер) в `systems/Audio.ts`. По умолчанию `muted=true` (офисный дежурный экран не должен шуметь без спроса), состояние в `localStorage`. `AudioContext` создаётся/резюмится лениво в обработчике клика по mute-иконке — это и есть тот самый user gesture, которого требует browser autoplay policy; никакой отдельной попытки создать контекст при загрузке страницы нет.
- **Одометр вместо мгновенного `setText`**: числа в HUD (`displayedTotal`/`displayedPlan`) анимируются тем же паттерном, что уже использовался для `displayedRatio` бара — tween плоского числового поля на самом Scene-объекте с `onUpdate`, а не встроенная в Phaser анимация текста.
- **Живой рейтинг** (`objects/Leaderboard.ts`) держит собственные строки-`Container`ы и твинит их `y` к новому рангу при каждом `DATA_UPDATED`; подписи — коды отделов через новый обратный маппинг `RosterConfig.ropNameForSlug()` (человекочитаемых имён персонажей пока не существует, намеренно не выдумывались).
- **`window.__debug`** расширен: `reachPen(delayMs)`, `pushStatus(partial)` (мёрджит в `GameState.byRop` и эмитит синтетический `DATA_UPDATED`), `audio` (прямой доступ к `AudioSystem` для ручной проверки тембра из консоли).

## Известные допущения
- **Точные колонки Google-таблицы, день начала недели** — допущения из плана, требуют сверки с реальной таблицей.
- **`ropMapping.json`** — маппинг на реальные коды отделов (СР1/2/3/5/6/9), подтверждено пользователем. Формат кода в самой таблице (регистр/пробелы) не проверен напрямую — если удары не анимируются, сверить точное написание в колонке ROP.

## Конвенции
- `src/game/core/` — EventBus, GameState, Constants (без Phaser-зависимостей, чистые модули).
- `src/game/scenes/` — Boot (генерация плейсхолдер-текстур) → Preloader (пытается загрузить реальные PNG, при отсутствии остаётся плейсхолдер) → PenScene + HUDScene (параллельные).
- `src/game/objects/` — Pig, HeroSprite, Leaderboard.
- `src/game/systems/` — DataPollingService (опрос backend, диффинг по РОПам), RosterConfig (маппинг героев), Audio (процедурный звук), Fx (переиспользуемые VFX-хелперы без ассетов).
- `src/game/config/` — `heroRoster.json` (фиксированный пул скинов), `ropMapping.json` (реальные имена РОПов → слаг героя, правится отдельно от кода).
- Dev-хуки в devtools (`import.meta.env.DEV` only): `window.__debug.hit(heroSlug, delta)`, `.reachPen(delayMs)`, `.pushStatus(partial)`, `.audio` — ручной триггер любого события без ожидания реального опроса.
