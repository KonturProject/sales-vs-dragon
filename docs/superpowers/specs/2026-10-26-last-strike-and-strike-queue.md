# «Показать последний удар» и очередь ударов героев — описание задачи

Дата: 2026-10-26. Заказчик: владелец проекта. Решения помечены: **[владелец]** — сказал он, **[моё]** — принял я.

## 1. Кнопка «Показать последний удар»

**Зачем.** Руководитель группы может показать сотрудникам на мониторе последнюю оплату: герой её отдела снова проводит удар.

**Как должно работать**
- На мониторе, в нижней строке (слева, рядом с кнопкой звука), стоит кнопка «Показать последний удар». **[владелец]**
- Нажатие проигрывает удар героя того отдела, чья оплата — последняя запись таблицы «Sales»; серия ударов, подпись «+N ₽» и реакция гоблина такие же, как у настоящей продажи, но это показ, а не продажа: итоги, таймер простоя и полоса не меняются (тот же флаг `demo`, что у ударов из админки). **[владелец + моё]**
- «Последняя запись» = оплата с самой поздней датой (при равных датах — нижняя строка листа), по всей таблице, а не только за эту неделю. **[моё]**
- Пока серия идёт, повторное нажатие игнорируется (кнопка бледнеет); пока данных от бэкенда ещё нет — кнопка недоступна. **[моё]**
- Данные берутся из публичного ответа бэкенда: новое поле `lastSale: { rop, amount, date }` — только отдел, сумма и дата, без клиента, ИНН и имён из таблицы. Это сознательное расширение прежнего правила «публичный GET отдаёт только итоги и команды». **[моё, нужен ваш взгляд]**

## 2. Очередь ударов: герои бьют по очереди

**Проблема.** При массовой загрузке оплат изменились суммы у нескольких отделов сразу, и их герои бросались на одного гоблина почти разом (разница 0,3 с).

**Правила** **[владелец]**
- Герои бьют по одному: следующая серия начинается, когда предыдущий герой закончил серию (и вернулся на место) плюс пауза.
- В момент загрузки оплат из файла пауза **3 секунды**.
- Во всех остальных случаях (живые продажи, удары из админки, кнопка «Показать последний удар») пауза **1,5 секунды**.

**Как делаем** **[моё]**
- Одна общая очередь на всю игру (`systems/StrikeQueue.ts`): каждый удар резервирует время «длительность серии + пауза»; следующий начинается не раньше. Очередь общая для всех опросов: удары из двух соседних опросов тоже не накладываются.
- Длительность серии считается по её настоящему числу ударов (2–4), а не по максимуму.
- Падение гоблина (потеря «головы») и финал ждут конца последнего удара очереди, как и раньше ждали конца ударов опроса.
- Как узнать, что идёт загрузка: бэкенд запоминает время последней загрузки (`importedAt` в публичном ответе, только после `replaceSales`). Если оно выросло с прошлого опроса — паузы по 3 секунды. Ручное внесение и удаление оплаты `importedAt` не меняют.
- Один удар на отдел за опрос (сумма прироста), как и раньше: 70 отдельных ударов по числу оплат смотрелись бы вечностью.

## Не цели
- Не менять сам удар (фазы, число ударов, эффекты).
- Не показывать на мониторе клиентов, ИНН, имена из таблицы.
