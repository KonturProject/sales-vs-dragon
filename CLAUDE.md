# CLAUDE.md

## What this is

"Отделы против орды" (repo `KonturProject/sales-vs-dragon`, renamed from `svin-i-zagon` on 2026-09-20; until 2026-10-22 the game was "Отделы против дракона") — a Phaser 4 + Vite + TypeScript browser game that visualizes a sales department's weekly plan on an office display. Six department mascots (Halloween versions) strike a goblin horde camped in a forest — five goblins guarding treasure, their chief behind them — whenever real sales land in a private Google Sheet; each of the 5 equal daily plans crossed (20/40/60/80/100 % of the weekly plan) defeats one goblin, whose treasure flies to the feet of the branch lead (Cruella), and at 100 % the chief sits down and cries and a victory banner appears. Cruella, not tied to a department, cheers on every sale. A separate PIN-gated admin page manages the game: weekly plan, reading and appending to the sales sheet, triggering animations on the displays, changing the PIN. Live at https://konturproject.github.io/sales-vs-dragon/ (admin: `/admin.html`); note the deployed site lags the code until `npm run deploy` is run.

**Start with `docs/NAVIGATOR.md`** — a lookup table of which file does what, who uses it, and where to go for a given task; use it instead of searching the repo. Keep it updated whenever files are added, moved or change role.

## Commands

All commands run from `game/` (the actual Vite project; the repo root is just a wrapper around it).

```bash
npm run dev            # dev server on :8080, hot reload
npm run build           # production build to game/dist (multi-entry: index.html + admin.html)
npx tsc --noEmit -p tsconfig.json   # type-check — there is no lint/test suite in this project; this is the only automated check
npm run deploy          # build + publish dist/ to the gh-pages branch (GitHub Pages)
python tools/build-sprites.py       # heroes (assets-source/hero-sheets) + Cruella (character-refs) -> public/assets/sprites (Python + Pillow + numpy + scipy); the old dragon/mountain/cave only with `--only dragon mountain bg`
python tools/build-horde.py         # goblins, chief (+ his sitting poses), treasure: assets-source/horde -> public/assets/sprites/horde + src/game/config/horde.json
python tools/build-background.py    # forest (face-tree moved left, widened for WORLD, darkened) + campfire: assets-source/background -> bg_forest.jpg, campfire.png
python tools/build-camp.py          # tent + totem (darkened): assets-source/camp -> camp_tent.png, camp_totem.png
python tools/build-hud.py           # Halloween HUD pieces (bar in 3 parts, big frame, small panel): assets-source/HUD -> public/assets/hud
python tools/build-sprites.py --only stance   # the breathing strips: assets-source/stance-sheets -> <hero>.png (frame 1) + <hero>_breath2..4
```

There is no test runner and no linter configured — `tsc --noEmit` is the only thing to run after a change, and manual verification in a browser is expected for anything visual (see Verification below).

## Architecture

**Two independent Vite entry points build from one project**: `index.html` (the Phaser game, `src/main.ts` → `src/game/`) and `admin.html` (a plain-DOM PIN-gated control panel, `src-admin/main.ts` + `api.ts`, no Phaser). Both are configured in `vite/config.{dev,prod}.mjs`, not a root `vite.config.ts`.

**Data flow**: a private Google Sheet → a standalone Google Apps Script Web App (`apps-script/Code.gs`, deployed separately — the copy in this repo is a mirror, not auto-synced) → `DataPollingService` (`src/game/systems/DataPollingService.ts`) polls it every 15s, diffs `byRop` against the previous snapshot, and emits events on the shared `EventBus` (`src/game/core/EventBus.ts`): `MONEY_IN` (per department, staggered), `PROGRESS_CHANGED`, `DRAGON_HEAD_LOST` (one per head, staggered), `DRAGON_DEFEATED`, `DATA_UPDATED`, `FETCH_ERROR`. `GameState` (`src/game/core/GameState.ts`) is the single source of truth both scenes read from; `GameState.headsRemaining = DAYS − floor(ratio × DAYS)` is the one place that defines how many goblins are still standing (a "head" is a goblin — the events and fields kept their dragon-era names on purpose). `RosterConfig` (`src/game/systems/RosterConfig.ts`) maps real department codes (`config/ropMapping.json`, e.g. `"СР1"`) to hero slugs (`config/heroRoster.json`).

**Two parallel Phaser scenes**, both launched from `Preloader`: `PenScene` (forest, heroes, the horde, the lead) and `HUDScene` (week bar with day dividers, head counter, victory banner, leaderboard, connectivity indicator, full-screen FX, mute button) — they communicate only through the EventBus, never call each other directly.

**Baseline gotcha**: the first poll after page load is a baseline — it must put the horde straight into the right state with no death animation (beaten goblins gone, their treasure already in Cruella's pile). `PenScene.create()` also calls `onProgressChanged` once with an *empty* GameState; that call must not consume the baseline (the flag is only set when `GameState.hasBaseline` is true), otherwise the horde loads with 5 goblins while the data says 4. Goblins only ever *fall* through `DRAGON_HEAD_LOST` (delayed so the hits read first) and only *come back* through `PROGRESS_CHANGED` (a new week) — keep it that way.

**Layout** lives in `Constants.ts` in logical 1280×720 units (the canvas *buffer* is `GAME.RENDER_SCALE`× that — see **Render scale** below): heroes stand in two staggered rows (`HERO.SLOTS`, depth = feet `y`) so neighbours never overlap, Cruella far left (`HERO.LEAD`) with the won treasure piling at her feet (`HORDE.LOOT`), the horde on the right of the forest road (`HORDE`: goblins in two rows, the chief behind, treasure at their feet, the campfire right of the chief), the face-tree of the background behind the heroes. The horde is deliberately static between events (no idle animation), and so are the heroes and Cruella: they stand on the floor and never bob up and down (removed at the user's request — they looked like they hovered); they "breathe" in turn instead (`BreathRelay`, see the 2026-10-24 section).

**Render scale**: the canvas buffer is `GAME.RENDER_SCALE`× the logical 1280×720 and every scene's camera is zoomed by it via `fitCameraToGame(this)` (`core/Render.ts`) — call it first in the `create()`/`preload` of any new scene, or that scene fills only a corner of the bigger canvas. `RENDER_SCALE` is **chosen per device at load** (`core/Quality.ts`: follows the real on-screen size in quarter steps, min 1, capped at 2 — 1.5 on the weak "low" tier), not a fixed 2. All coordinates stay logical (use `GAME.WIDTH/HEIGHT`, never `scene.scale.width/height`, for full-screen effects). Every `add.text` style needs `resolution: GAME.RENDER_SCALE` or the text is rasterised at 1× and comes out blurry. `public/style.css` forces `image-rendering: auto` on the canvas (Phaser's `pixelArt` would set `pixelated`, uneven at non-integer scaling), and `Preloader` sets LINEAR filtering on the sprite/background textures (NEAREST is jagged at 1.25×/1.5×).

**Performance / frame rate** (`core/Quality.ts`, `core/PowerSaver.ts`): the game runs on the team's weak laptops (2-core i3, integrated graphics) as an always-on display, so it must not redraw a still picture 60+ times a second. Phaser's `fps.limit` is set from the quality tier (`low` = `hardwareConcurrency ≤ 4` or `deviceMemory ≤ 4`: 30 fps active; `high`: 60) and `PowerSaver` retunes `game.loop._limitRate` at run time: **active** while a finite tween runs or a `MONEY_IN`/`DRAGON_HEAD_LOST`/`DRAGON_DEFEATED` event is recent, **ambient** (20 fps) while only endless pulsing tweens run (victory banner, Cruella), **idle** (10 fps) otherwise. Rules that keep it idle: don't start tweens for unchanged values on every poll (`HUDScene.render`, `Leaderboard.update` skip no-ops), and don't add per-object random timers that start animations — the breath goes through one shared relay (`BreathRelay`), on timers. Any new always-running animation costs battery on every office laptop: make it a finite tween or accept the ambient rate. URL overrides for testing on a specific machine: `?quality=low|high`, `?scale=1.25`, `?fps=30`, `?idlefps=5`. See `docs/tech.md`, "Производительность".

**Idle mood** (`systems/IdleMood.ts`, tuned by `IDLE` and `DRAGON.GROWL_*` in `Constants.ts`): with no sale for an hour of *game* time (the whole team, deliberately not per department; it restarts from zero on page load and stands still while the tab is hidden), one random hero keels over (`HeroSprite.fallOver`: stagger, topple ±90° about the feet with the body lifted half its thickness onto the floor line, bounce, dust, thud) or dozes off standing (`doze`), one more per further hour, max `IDLE.MAX_DOWN`, at most `MAX_LYING` lying at once (tight rows); sleepers show a static "Zzz" and rarely a floating "Z"; any sale wakes everyone (`MONEY_IN`, staggered), and `playHit`/`playCelebrate` wake their hero instantly. The chief taunts on its own every 1.5–3 min (40–80 s while the team is idle, and 1.3 s after each drop): `Horde.growl` (his attack sheet, the goblins swing their weapons too, camera rumble, `AudioSystem.playGrowl`), cut short by any hit/goblin loss/new week/defeat (`cancelGrowl`). Everything is a finite tween or a static pose on purpose (an endless one would keep the laptops out of idle frame rate). Page URL `?idle=<minutes>` shrinks the one-hour thresholds to show it without waiting; `__debug.mood().advance(ms)` / `.dropOne()` / `.wakeAll()` / `.state()` and `__debug.growl()` in dev.

**Admin panel & backend API** (`src-admin/`, `apps-script/Code.gs`; full table in `apps-script/README.md`): the admin page logs in with the PIN (kept in memory only), then has tabs — plan (+ the month's average check, `setAvgCheck`), sheet viewer (`listSales`), append a payment (`addSale`, with a confirm dialog: it is a real sale), **upload payments** (an .xlsx from the accounts system, parsed in the browser by `src-admin/importPayments.ts`; the period is taken from the file's first/last «Дата оплаты» and editable; `countSales` previews what is there, `replaceSales` replaces every sale of the period — admin writes are confirmed and idempotent on `requestId`), animation buttons (`command`), change PIN (`changePin`). The average check (public GET `avgCheck`, `GameState.avgCheck`) decides how many blows a payment gets (`blowsFor`: <0.5×avg → 2, <1.5×avg → 3, else 4 + the comic text; unset → by amount). **Animations are commands, not data**: the admin POSTs `{action:'command', type, args}`; the backend keeps the last 10 (fresher than 10 min) in Script Properties — never in the spreadsheet — and hands them out on the public GET as `commands` + `serverNow`; `DataPollingService.dispatchCommands` plays each id once as an `ADMIN_COMMAND` event (first poll after page load only sets the baseline, no replay; commands older than `POLL.COMMAND_MAX_AGE_MS` by the *backend's* clock are dropped). Handlers (`PenScene.onAdminCommand`, `HUDScene`) are visual only: a `hit` is a `MONEY_IN` flagged `demo` (does not reset the idle timer). Delay ≈ the poll interval (≤15 s). The PIN is stored as a salted hash (a legacy plain `ADMIN_PIN` property still works until the first PIN change), wrong PINs lock the API for 10 min after 5 tries, admin writes take a script lock and dedupe on `requestId`. **The real sheet is not tidy**: column F holds the list behind the ROP drop-down and column D holds names, so `getLastRow()` overstates the sales (rows are judged by Date/Amount/ROP — `isBlankSale_`), `addSale` writes only the three cells into the first free sales row (never `appendRow`), and sales dates are date-only (midnight). **Never delete whole sheet rows** (that shifts the drop-down list) — clear cells instead. Polling copes with Apps Script's slow tail (median ~3 s, sometimes 10–40 s, and a cold instance can hang the first request after page load): 30 s timeout per attempt, a second identical request joins after 6 s or on an outright failure and the first success wins (`fetchWithHedge`), one poll in flight at a time, "offline" only after 2 failed polls in a row. **`Code.gs` is deployed by hand** (Apps Script editor → Deploy → Manage deployments → New version); test it locally first: `npm run test:backend` runs the real `Code.gs` against fake Google services, `npm run mock-backend` serves it on :8787 (dev pages accept `?backend=http://localhost:8787/exec`).

**Delayed events go stale**: head loss and victory fire after a delay (so the hits read first) and the data can change meanwhile (plan raised mid-cascade). Handlers re-check `GameState` before showing anything, and `Horde.headCount` is the *target*; frame animations run as counter tweens (`playFrames`) that stop as soon as another state has changed the sprite's texture — keep those guards when touching `PenScene`/`HUDScene`/`Horde` (see `docs/tech.md`).

**Tween ownership**: nothing tweens a hero's `y` any more (no idle bob). The hit chain (`HeroSprite.playHit`) owns `x`/scale/angle and kills other tweens on the hero when it starts (`killTweensOf`); the breath is texture swaps on timers and is skipped while `busy`. Cheer/celebrate reactions touch scale only. Two tweens on the same property make sprites visibly jump when one ends.

**Hero strike**: on a sale the hero takes its next attack (four per hero, round-robin): it shows the attack's wind-up frame while it runs along its own row until its leading edge (weapon/fist/fire, from the blow frame's texture width) reaches `Horde.strikeFrontX()` (the front of the nearest goblin still standing, then the chief; `HERO.STRIKE_FRONT_X` is only the fallback), the blow lands *on arrival* — the blow frame with its fire/glow/slash appears (`HERO.IMPACT_MS` after the event — burst, shake, ring, comic text, the goblin's reaction, the thud and Cruella's cheer all key off it), then the hero turns (`flipX`) and walks back. Phase lengths are `HERO.WINDUP_MS/RUN_MS/RECOIL_MS/RETURN_MS`; `HIT_DURATION_MS` (used by `DataPollingService` to time head loss after the blows) is derived from them — change the phases, not the sum. (In the dragon era, sending every hero down to one spot in front of the gold pile was tried and rejected — "they hit the gold".) A front-row hero covering a back-row one during the run is accepted.

**Sprites are built, not loaded raw**: the game loads `public/assets/sprites/*`, which `game/tools/build-sprites.py` generates. **Heroes** come from one 4×4 sprite sheet each (the user's Halloween versions, since 2026-10-22) in `game/assets-source/hero-sheets/<СРx - name>/sheet.png`: the script cuts the 16 frames by connected pieces (a sword or a fire trail may cross the cell line), takes the stance and four attacks of two frames each — wind-up `hero_x_hitN_windup`, blow `hero_x_hitN` (which cells: `HERO_SHEETS`, chosen by eye) — puts every frame on a canvas whose bottom is the feet line and whose centre is the body (from the feet, not the bounding box), scales them together to the old standing heights ×2 and saves palette PNGs (`hits` = 4 in `heroRoster.json`). The user's working folder `heroes/new hero/` at the repo root is not committed. **Cruella** still comes from `game/assets-source/character-refs/` (as do the old dragon, gold mountain and cave, no longer in the game — their sprites were removed from `public/`). **The horde** is built by `tools/build-horde.py` from free hsdsz sheets in `game/assets-source/horde/` (400×400 cells, facing right → mirrored, one frame box per creature for all its animations, origin = feet, palette PNGs, metadata in `src/game/config/horde.json`); the chief's sitting/crying poses are `goblin-chief/sit.png`, drawn for this game by the user — a pose a pack lacks is drawn, not pieced together from other frames (that was tried and rejected). **The background** is built by `tools/build-background.py` from the layered CraftPix forest in `game/assets-source/background/` (the face-tree layer moved left, behind the heroes). All sources are committed (the user's decision, 2026-10-22), except the background's PSD. Hero, Cruella and treasure textures are at 2× screen size (shown at scale 0.5); the horde's frames keep their sheet size (`HORDE.GOBLIN_SCALE`, `HORDE.CHIEF.scale`). Don't hand-edit files in `public/assets/sprites/` — change the source art or the script and rebuild.

**No glow/shadow effects on characters** — deliberately removed per user feedback; don't reintroduce them without being asked. Character art is finished by the user (Fooocus generation + Photoshop cut-out with real alpha), so don't run background-removal scripts on it.

**Debug hooks** (`window.__debug`, only in dev builds): `hit(heroSlug, delta)`, `setRatio(0..1)` (pushes a synthetic status through the real diff pipeline: hits, head loss, victory), `injectStatus(status)`, `poller.stop()` (call this first when testing by hand — otherwise the next real poll overwrites your injected state), `audio`, `power()` (current frame-rate mode and the rate frames are really drawn at), `mood()`, `growl()` (the chief's taunt), `command(type, args)` (what an admin animation button causes), plus direct access to `EventBus`/`GameEvents`/`GameState`/`game`.

**Image generation** (Fooocus, SDXL + pixel-art LoRA) runs locally outside this repo, started by the user; the operating guide is the `fooocus` skill in `~/.claude/skills/`. Findings that matter here are in `docs/tech.md`.

## Verification

This project has no automated visual tests. The established workflow for any UI/animation change: start the dev server, open it in a browser, `__debug.poller.stop()`, drive the relevant event with `__debug.hit`/`setRatio`, and confirm — screenshots are unreliable for fast animations, so also read object state (`texture.key`, `horde.headCount`, `horde.goblins[i].alive`, `horde.chief.sprite.texture.key`, `hud.banner`) via `__debug.game.scene.getScene('PenScene')`. `npx tsc --noEmit` catches type errors but proves nothing about runtime behavior.

## Backend / secrets

The Apps Script admin PIN lives only in that script's `PropertiesService`, never in this repo or its docs (the source in `apps-script/Code.gs` has a placeholder). The Apps Script Web App URL in `game/public/config.json` is intentionally public — its public GET only serves aggregated totals and animation commands, never raw sheet rows (raw rows come only through PIN-gated `listSales`); this was an explicit, confirmed decision, not an oversight. See `docs/MAP.md` for the real Sheet URL, Web App URL, and deploy details.


## Camp scene, breathing, strike series, HUD (2026-10-24)

Spec `docs/superpowers/specs/2026-10-24-camp-scene-design.md`, plan `docs/superpowers/plans/2026-10-24-camp-scene.md`.

- **Wider world**: `PenScene` uses `fitCameraToWorld` (`core/Render.ts`): its camera is zoomed out by `WORLD.ZOOM` (0.72, `Constants.ts`), so the stage shows `WORLD.W × WORLD.H` (≈1778×1000) around the logical 1280×720, reaching `WORLD.X0/Y0` (negative) past the edges. `HUDScene` keeps the plain 1280×720 camera. `bg_forest.jpg` (2667×1500) covers the whole view; `tools/build-background.py` must use the same `WORLD_ZOOM`. Stage → HUD coordinates: `hudToWorld`. Hero/goblin/chief sizes are relative to a hero (~215 world px with `HERO.SLOTS[].scale`): goblins `HORDE.GOBLIN_HEIGHT` (scale per def = height / `topPx`), chief `HORDE.CHIEF.height` (a hero ×1.5).
- **Camp**: goblins in a half-ring round the campfire (`HORDE.GOBLINS`, `CAMPFIRE`), chief behind, two tents (`TENTS`) and two totem "gate" posts (`TOTEMS`) drawn by `objects/CampProps.ts` (mirrored, bigger the nearer the bottom). `objects/Firelight.ts` = additive glow *under* all characters, flickering with the fire's own frames (no tween/timer).
- **Breathing** (`systems/BreathRelay.ts`, `BREATH` in `Constants.ts`): heroes and Cruella play the user's weight-shift strips (`<hero>` = frame 1, `<hero>_breath2..4`), goblins and chief a 4-step scaleY (`breatheScale` in `Horde.ts`), two at a time, passed round. **Timers and texture swaps only — never tweens**: `PowerSaver.tweenMotion` counts any ordinary tween as active motion. The old random tilt (`startIdleSway`) was removed.
- **Strike series**: one sale = `blowsFor(delta)` blows (2..4, `HERO.BLOWS`) on the nearest goblin; `HeroSprite.playHit(delta, strikeFrontX, onBlow)` calls `onBlow(index,total)` as each lands (thud, goblin reaction, Cruella's cheer on the first). `HERO.HIT_DURATION_MS` covers the longest series — the goblin's fall waits for it.
- **HUD** (`HUD` in `Constants.ts` holds every position/size/colour): the weekly bar is the user's pumpkin-and-lantern frame in three pictures (left, middle stretched, right; `public/assets/hud`), the fill is drawn in code between `TRACK_INSET_LEFT/RIGHT`; the leaderboard sits on the small panel (`HUD.PANEL`), the victory banner on the big frame (`HUD.BANNER`). Font is a system serif (`HUD.FONT`) until a Halloween font is bundled.
- **Seeing the real picture**: the in-app browser pane is small; for pixel checks use `__debug.game.renderer.snapshot(img => …)` and POST the PNG to a throw-away local receiver, then `Read` the file.
